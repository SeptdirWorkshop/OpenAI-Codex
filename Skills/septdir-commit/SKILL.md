# Подготовка и создание коммита

Разрешения и формат token — в корневом `AGENTS.md` проекта.

## Подготовка

1. Прочитать текущую ветку, HEAD, Git status, staged- и unstaged-diff;
   новые неигнорируемые файлы — с диска. При подготовке index не менять.
2. Состав брать из запроса или предложить по текущим изменениям.
   Различать содержимое index и рабочих файлов, удаления и переименования.
3. Перед gate выполнить [septdir-inspect](../septdir-inspect/SKILL.md) для новых, изменённых и переименованных файлов,
   выбранных для коммита.
   Если содержимое index отличается от рабочих файлов, явно указать ограничение диагностики.
4. Показать состав и смысл коммита, название на английском, замечания инспекций и изменения, остающиеся вне коммита.
   Затем показать gate и остановиться.

## После create_commit

1. Повторно сверить ветку, HEAD, index и согласованное содержимое.
   При изменении ветки, HEAD, состава, содержимого или названия вернуться к gate.
   Изменённые файлы проинспектировать повторно.
2. Подготовить только согласованное содержимое по явным путям.
   Не использовать `git add .` и не обходить `.gitignore`.
   Сохранить чужой и частичный staging; если это невозможно,
   остановиться и согласовать действие.
3. Сверить итоговый staged-diff с согласованным составом
   и создать один коммит с согласованным названием.
   При ошибке проверить фактическое состояние HEAD и index;
   не скрывать сбой повторными коммитами или правками.
4. Сообщить hash, название и оставшиеся staged, unstaged и untracked-файлы.
