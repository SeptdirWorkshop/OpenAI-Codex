# Написание кода

Прочитать [общие правила кода](../code-rules/common.md); порядок работы, разрешения и работа с MCP —
в корневом `AGENTS.md` целевого проекта.

Прочитать правила затронутых языков:

* [JS/TS](../code-rules/js-ts.md).
* [PHP](../code-rules/php.md).
* [C#](../code-rules/csharp.md).
* [Python](../code-rules/python.md).

1. Прочитать реализацию, контракты и потребителей; определить владельца задачи и простое решение.
   До правок пройти gate. При `edit_user` выдать код в чате и закончить.
2. При `edit_agent` внести согласованные изменения. Новые неигнорируемые файлы, созданные агентом в рамках согласованных
   изменений, сразу добавлять в Git по явным путям: `git add -- путь1 путь2`. Существующий staging сохранять;
   при отсутствии репозитория сообщить, что файлы не добавлены.
3. Форматировать затронутые поддерживаемые файлы последовательно через `reformat_file` выбранной IDE с настройками проекта,
   по одному файлу за вызов. Следующий вызов начинать после завершения предыдущего.
   Проверить изменения, итоговое содержимое и соблюдение стандарта кода: автоформатирование не заменяет проверки
   структуры кода.
   Выполнить [septdir-inspect](../septdir-inspect/SKILL.md) для затронутых существующих файлов.
   При сбое MCP следовать AGENTS.md; невыполненные проверки не считать успешными.
4. Исправить errors/warnings своих правок в пределах согласованного объёма. Повторять форматирование и инспекцию
   только изменённых файлов; остальные замечания и вопросы ответственности вынести в обсуждение.
5. Сообщить итог по правилам AGENTS.md.
   Коммит — отдельный [septdir-commit](../septdir-commit/SKILL.md).
